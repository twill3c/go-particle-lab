Go Particle Lab 設計図

物理は全部 Go に置き、JavaScript には運動則を一行も書かない。その境界をどう引き、どう「守られていること」を機械で確かめたか。作っている途中で捨てた設計と、検査が全部緑のまま通り抜けた欠陥の記録。

層

internal/physics粒子・積分・壁・障害物・粒子同士の衝突(一様格子)・重力井戸・ブラックホール。syscall/js を import しないのでネイティブで go test が走る
internal/gameステージ 7 種・Goal 判定・スコアとコンボ・制限時間・井戸の操作・Pause/Reset
internal/bridgeGo → JS の状態 JSON の型。ここも syscall/js に依存しないので、キー名の契約をテストで固定できる
cmd/wasmsyscall/js の橋渡しだけ。GOOS=js GOARCH=wasm でここだけが Wasm になる
web/app.jsCanvas 描画・マウスとタッチ・スライダー・Lab Mode。運動則は持たない

粒子の座標は毎フレーム JSON にしない。Go 側で []float32 に (x, y) を詰め、js.CopyBytesToJS で JavaScript の Float32Array の buffer へ 1 回だけコピーする。5,000 粒子で 40 KB。JSON にするのはスコア・時間・井戸の位置など数十個の値だけ。

境界をまたぐ契約は、テストできる場所に置く

最初は状態 JSON の型を cmd/wasm に書いていた。そこは syscall/js を import するのでネイティブで go test が走らない。テストできない場所に契約を置くと、契約は検査されない。

捕まえられなかった欠陥 構造体に json タグを付け忘れ、キーが X/Y/W/H のまま出た。JavaScript は x/y/w/h を読むので、井戸も Goal も障害物も画面に描かれない。Go のテスト 24 件は緑、Wasm ビルドも緑、JavaScript 側の「運動則を持たない」検査も緑のまま通り抜けた。実ブラウザ検品のドラッグ検査が moved.x が undefined で落ちて初めて分かった。

直し方は、タグを足すことではなく置き場所を変えることだった。JSON の型を internal/bridge に移し、次の 2 つを見るテストを置いた。

  • Marshal した結果の全キーが小文字始まり(入れ子も再帰的に走査する)
  • app.js の実物を読んで s.xxx / w.xxx / o.xxx の参照を正規表現で拾い、そのキーがすべて JSON に存在する。拾えた参照が 20 個未満なら「走査パターンが壊れている」として落ちる

遊び方を、自動プレイで測って組み替えた

仕様書の段階では「重力井戸を置いて粒子を Goal へ導く」だった。そのまま実装し、井戸を Goal の手前に 1 つ置く自動プレイで測ったところ、こうなった。

Stage60 秒での到達数(3 seed)目標 100 に
1 Free Float100 / 100 / 101届く
2 Gravity3 / 2 / 4届かない
3 Obstacles8 / 15 / 10届かない
5 Wind3 / 3 / 0届かない
7 Black Hole2 / 1 / 3届かない

逆二乗の井戸(距離 300 px で 22 px/s²)は重力 300 に遠く及ばず、床に溜まった粒子を持ち上げられない。導けるのは重力が無いステージだけだった。井戸を強くしても、床の粒子は井戸に貼り付くだけで Goal へは動かない。

そこで遊びの動詞を変えた。原本の操作表には最初から「ドラッグで井戸を移動」がある。井戸の内側に入った粒子の速度を減衰させれば、粒子は井戸に落ち着き、井戸ごと運べる。「導く」ではなく「捕まえて運ぶ」。物理に足したのはこれだけ。

強さの較正

次は「1 往復で何個運べるか」を実測で決めた。最初に置いた Strength 2e6 / Radius 320 は 1 往復で 250〜380 個さらい、10 秒でゲームが終わった。

Strength1 往復で運べる粒子判断
0.8e6約 502 往復でも足りない
1.0e6約 80採用。1〜2 往復
1.3e6約 1251 往復で終わる
2.0e6250〜38010 秒で終わる

半径のほうは 90 px から 320 px まで振っても運搬量がほとんど変わらなかった。運ぶ量を決めるのは引力の強さで、届く範囲ではない。採用は Strength 1.0e6・Radius 130・捕捉半径 40・減衰 4/s。この 4 つの数はゲームの手触りそのものなので、G-07 がゲートとして張ってある。誰かが定数を触れば、遊べなくなった時点でテストが落ちる。

検査が全部緑のまま通った欠陥、3 つ

1. 一時停止のバナーが消えない .banner { display: flex } が HTML の hidden 属性に勝っていた(ブラウザ標準の [hidden] { display: none } と同じ詳細度なので、後から書いた著者側のルールが勝つ)。状態を読む検査は「playing」を返し続け、すべて緑。スクリーンショットを目で見て見つけた。以後、バナーは状態ではなく getComputedStyle の実際の表示で検査している。
2. 60 秒に 1.3 ピコ秒だけ届かない 残り時間を 60 − Σdt で出していたので、0.05 秒を 1,200 回足しても 60 に届かず、時間切れにならない。浮動小数の累積。仕様が保証している粒度は秒なので、1 ナノ秒未満は 0 とみなすことにした。
3. これは私の検査の側が壊れていた 本番相当のブラウザでマウスドラッグの運搬が 0 個になった。アプリを疑って切り分けたが、原因は検品スクリプトが RESET ボタンを押した後ページがスクロールしたのに古い canvas 座標を使い続けていたこと。mousedown が canvas に届いていなかった。失敗の分類を「検証の穴」から「誤検知」へ訂正して記録し直した。赤も疑う。
